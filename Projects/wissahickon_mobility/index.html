Wissahickon Park Mobility & Visitor Access Analysis

A methodology proof-of-concept for park usage & catchment analysis
QGIS Python / Pandas qgis2web / Leaflet Esri World Topo

Municipal park systems rarely have good visibility into how people actually move through and access their trails, without field-based visitor counts, agencies are largely guessing at which entry points, facilities, and trail segments see the most use, and how far people are traveling to get there.

This project tests a methodology for answering those questions using mobile Location-Based Services (LBS) data layered against physical park infrastructure — trail networks, boundaries, and structures — for the Wissahickon Valley park system in Philadelphia. To demonstrate the spatial pipeline without proprietary commercial feeds, this proof-of-concept utilizes a simulated LBS ping dataset modeled on typical urban trail usage patterns. Full methodology and code linked at the bottom of this page.

Methodology

Technical pipeline

  • Desktop GIS: QGIS 3.x — network segmentation, spatial filtering, vector symbology.
  • Spatial analysis: PyQGIS & Pandas — LBS ping aggregation, corridor-adherence buffering, travel-catchment metrics.
  • Export engine: qgis2web plugin, exporting to a native Leaflet.js implementation.
  • Basemap: Esri World Topographic Map.
  • Front-end customizations: custom fill opacity, persistent event-driven popups, auto-collapsing mobile layer control tree.
  • Code & write-up: full README and source available on GitHub.
Limitations & Next Steps

Scoping this as a proof of concept

This is intentionally scoped to test the pipeline, not to deliver production-grade visitor metrics. A full deployment would extend it with:

  • Real vendor LBS data: sourced from a licensed commercial provider under a paid data-use agreement, replacing the simulated dataset.
  • Multi-season / multi-year comparison: capturing seasonal usage shifts rather than a single snapshot.
  • Ground-truthing: cross-validating LBS-derived hotspot estimates against trail counters or gate logs where available.
  • Expanded catchment resolution: adaptive geography (ZIP codes or counties) for larger or more rural park systems.
